# Session — 2026-10-01 — Phase 2, command engine

## What this session did

Delivered Phase 2: natural-language sentence input, parsed by a language model, applied by the
Phase 1 executor. A sentence such as `used 2 onions` or `bought banana 10 rupees cash` now
reaches the database through the same validated pipeline the structured forms already used.

| Path | Role |

Decisions are ADR-040 (the parser port and the trust model), ADR-041 (a second entry point,
never a second execution path), and ADR-042 (the origin guard).

## Not verified

- **No live OpenRouter call was ever made.** Neither `OPENROUTER_API_KEY` nor
  `OPENROUTER_MODEL` was available in this environment. The provider is tested against a local
  HTTP stub (`chat:test` section 37) and an injected transport (`parser:test` section 21), so
  the request this application builds is asserted field by field — but the model id, the
  account, and whether a real provider accepts the schema are untested. Everything up to the
  socket is verified; nothing past it is.
- **Two pre-existing lint gaps were found and left open.** `src/lib/db` may import

  Neither is exercised by current code, both predate Phase 2, and closing them is an
  architecture change that needs an ADR. Recorded in `PROJECT_STATUS.md` under *Not verified*.

## Mistakes made in this session

Recorded because the corrections are the useful part.

**1. `chat:test` wrote to the real development database.** The first draft created a fresh
database per case and imported the engine statically. The engine reaches storage through the
Phase 1 composition root, which resolves the path from `HARI_OS_DB_PATH` on first open and
caches the handle, so it wrote to `data/hari-os.db`. The commands failed as `unknown_item`
because that database has no inventory rows, so **nothing was written and the fingerprint never
changed** — but the test was silently exercising the wrong database, and passing for the wrong
reason. The fix was to set `HARI_OS_DB_PATH` before any storage-touching import, which is why
the file has no static import of the engine. Isolation has to be established before the first
import, not after. The fingerprint assertion now in the file is what would catch a repeat.

**2. Six test expectations were wrong, not the code.** Balances asserted as `49900` where
₹500.00 − ₹10.00 is `49000`; a forged-balance case that asserted a proposal must be *refused*
when the correct behaviour is that its junk fields are dropped and the legitimate facts execute.
Each was a test bug. The forged case was rewritten to assert the stronger property — the
resulting balance is the domain's, not the model's — rather than deleted.

**3. The route had no tests at all, and shipped a CSRF hole.** `POST /api/commands/parse`
accepted any origin. Because it is a write and V1 has no session, any page the user had open
could post a form to `localhost` and cause a command to run. It passed the suite because no test
ever posted to the route. Found by direct HTTP acceptance, fixed in ADR-042, and the route now
has direct handler tests.

**4. The origin guard broke the app for users on `127.0.0.1`.** The first fix compared `Origin`
only against `request.url`. `next start` derives its own canonical hostname, so a request that
genuinely arrived at `127.0.0.1:3111` is seen as `localhost:3111` and the application's own
users were refused. Caught by re-running the same-origin curl that had just been fixed. The
guard now accepts the `Host` header as well. A guard that refuses the app is worse than none.

**5. `openrouter.ts` was destroyed and rewritten.** A boundary probe did
`cat > src/features/chat/openrouter.ts` instead of writing a new probe file, and the following
`rm` deleted it. It was untracked, so there was no git history to recover from and it was
rewritten from the contract its callers and tests imply. The reconstruction initially lost two
things a test then caught: the injectable transport parameter, and the rule that content which
is not JSON is returned as a string for `interpret` to refuse rather than failed at the
transport layer. The provider now has direct coverage it never had.

**6. Removing "unused" imports broke a script.** Imports were pruned on a `grep 'name\.'` count,
which misses bare calls like `fileURLToPath(import.meta.url)` and identifiers used as values.
Two working imports were removed and the script crashed. The lesson is that a grep count is not
evidence; running the script is.
