## What this phase was

Eight phases had built the features. None of them asked what happens when the layers disagree with
each other, so this phase did. Its output is not a feature; it is a list of defects that were real,
a lint rule that makes two of them impossible to reintroduce, and a test suite that follows each
fact through every layer it has to cross.

## A scope correction, made before any code

The phase document said *"the application must work offline"*. ADR-059 caches nothing and accepts
that a browser reload without a server has nothing to show. The two cannot both be true.

ADR-059 is accepted, so **offline operation is not product scope and was not built.** What was
verified is the narrower claim that survives: no code path reaches the network for anything it did
not choose to. No telemetry, no remote fonts, no CDN, no fetch outside the LLM call the user asked
for.

The phase document was corrected at the top of this phase rather than at the end, so the record
shows the decision rather than the correction.

## Defects found, and what each one was

Reading each module against the claim it was supposed to satisfy found eleven. The full table with
fixes is in `docs/phases/PHASE_09_HARDENING.md`; the ones worth explaining here are the three that
were not obvious.

### Private text in a response nobody rendered

`TodayEntry` was assembled from the whole `habit_log` row, which has a `note` column — so the Habits
read model returned a field no page on that screen renders. The command endpoint then serialised the
executor's full `HabitLog` value, note included, in the JSON response of every habit and private
command.

The note was never *displayed*. That is the point: "we do not render it" is a claim about a page,
and the defect was in a type. The value was in a response a browser could log and any middlebox
could cache. `HabitCommandView` is now the only habit type the command layer returns, and it has no
field a note could occupy. Recorded as ADR-061.

### An invariant enforced by a convention

Five files could read private or diary text. The list lived in one person's memory and nothing
failed when a sixth joined it. That is the failure mode the ADR-060 lint scopes already guard
against everywhere else, so the same treatment applied: enforced in `eslint.config.mjs` through one
shared constant.

ADR-060 already records that `no-restricted-imports` *replaces* its pattern list rather than
merging it, and that ESLint 9.39's schema has no `overrides` key. A second config object carrying
only the new pattern would have silently removed every existing rule from every file it matched.
That is why this is a shared constant and not a second scope. The failure mode is worse than the
error message suggests, and it was already paid for once.

### A committed branch that did not build

The last commit of the defect series, `9e90b4d`, changed three routes to build their outcome URL
through `outcomeRedirect` and committed the callers without the function. Three `TS2305` errors,
and `npm run typecheck` would have failed on a clean checkout.

It passed locally because the uncommitted function was sitting in the working tree. This is the
failure mode AGENTS.md section 9 already warns about in a different form — verification that reads
the working tree rather than the commit. Confirmed by reverting the file and watching `tsc` fail,
then restored. Fixed in `9467ac8`.

Recorded rather than quietly amended, per AGENTS.md section 13.

## The regression suite

The fourteen existing suites each test one layer against the one below it, which is the right
structure and leaves a specific gap: none of them asks whether a change made by one module is
visible, and correct, in a module that has no other way of knowing it happened.

`scripts/regression-test.mjs` has twelve sections that each follow one fact through command,
validation, domain, SQLite, read model, and page. Kitchen stock consumed by a sentence is the
number the Kitchen page shows. A balance is the number both the Expenses page and the Dashboard
report, and the same command from the same state subtracts the same amount twice. A task created
for tomorrow is the task the Routine page lists under tomorrow. A photo stored through the camera
endpoint is the same diary entry a gallery upload would have written, through the same code path.

Section 10 is the one about the LLM boundary. A proposal carrying `balance: 0`, its own `id`, and
its own `timestamp` alongside a valid spend: the stated amount is applied, and the three fields a
model has no business supplying are ignored — the balance is not written to zero, the row number is
the database's, the timestamp is the clock's. A second half then proposes consuming more stock than
exists and asserts the refusal cost nothing to write.

Section 12 closes the database and reopens it, because a read model served from a cached handle
proves nothing about what survives a restart. It also asserts the stored image is still on disk,
reachable only through its route.

87 assertions. Real SQLite, a disposable database in the OS temp directory, the development
database fingerprinted before and after.

Writing it against the real modules was the point — every section's first draft was wrong about
something, because the type in the source is the only authority on what the read model returns.

- `git ls-files` finds no tracked `.db`, `.db-wal`, `.db-shm`, `.sqlite`, or `.sqlite3`.
- `git ls-files` finds nothing under `data/`.
- `git check-ignore -v` on **real** files, not on the pattern text: `data/uploads/probe.png` and
  `data/probe.db` both match `.gitignore:37`, `.env.local` matches `.gitignore:25`. Probes deleted.

  tracked and contains documentation and safe examples only.

  land in the developer's own uploads directory.

## Accepted limitations

Seven, recorded in the phase document rather than fixed: no idempotency keys, no rate limiting,
request-size limits only for photos, `Origin` may be absent, generic redirect queries must go
through `outcomeRedirect`, a corrupt database fails loudly rather than coercing, and photo orphan
cleanup is not automatic. Each is a decision with a reason, not an oversight.
