### A real bug the tests caught

The first `db:check` passed, which was reassuring and not sufficient. `db:test` was written
to try inserting a float into a money column, and it succeeded:

```
INSERT INTO expense (timestamp, item, amount, account)
  VALUES ('t', 'x', 10.5, 1)     -- accepted
```

`amount` was declared `INTEGER`, but SQLite uses type *affinity*, not enforcement: a column
declared `INTEGER` will still store a `REAL`. An `INTEGER` column alone does not mean
integer storage, and the PRD requires deterministic balances.

Fixed by adding explicit `typeof()` checks, applied consistently across every structurally
typed column — money, booleans, whole-minute durations, and numeric quantities. Three
additional cases were then added to the suite to cover the columns the original bug had not
touched: `habit_log.done`, `skill_log.minutes`, and a non-numeric `inventory_event.delta`.

Recorded as ADR-023.

### The local database

it, every table was counted:

```

```

The single row was the `schema_migrations` record created by that unreleased migration.
Zero user data. `001_initial` was never committed, so correcting it in place was the right
action rather than shipping a known-wrong migration plus a fix-up. The file was still copied
to a backup first, then recreated via `npm run db:check`, then the backup was removed only
after the corrected constraints were confirmed live.

The real database was left holding only its migration record.

## Mistakes made and corrected

- The initial `db:check` passed while the schema was still wrong. Treated a green check as
  evidence of nothing; the test suite is what found the defect.
- The first attempt at the `typeof` fix covered money but not booleans, durations, or
  non-numeric quantities, which would have left the same class of bug in five columns. Fixed
  by applying the rule consistently and adding tests for the columns not already covered.
- A duplicated `## Known Issues` heading and stale "Phase 0" framing were introduced into
  `ARCHITECTURE.md` while editing. Caught and corrected before commit.
- `PROJECT_STATUS.md` carried a "schema is empty by design" claim that became false the
  moment the schema landed. Updated in the same commit rather than left to drift.
