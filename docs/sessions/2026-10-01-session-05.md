## The three decisions that shaped it

1. **The check-in is an operation, not a command** (ADR-049). It writes four rows and is
   worthless if half of it lands, so it is one transaction behind `POST /api/routine` with a
   closed enum of one operation. A `night.check_in` command carrying a list of three titles plus
   a boolean would have been the first multi-fact command in the system and would have needed
   list validation, another executor branch, and parser support for a shape no sentence
   produces — all to say what three `task.create` commands already say.
2. **`plan_task` has one reader** (ADR-050). ADR-047 accepted `display.tasksForDate` only while
   no feature owned the table. Routine does now, so the Dashboard composes `readRoutine` and the
   ad-hoc read is deleted. That is how the Dashboard gained the sleep card without a second
   definition of "today's tasks".
3. **The streak is neutral and the pages say so.** A count of consecutive days with a wake time
   inside 06:15–07:30, rendered as a record. The window itself comes from the domain, not from
   the JSX, so the page cannot quote a different range than the rule uses.

## The zero-threshold discrepancy, resolved

Phase 5 found and recorded a mismatch and left it as the user's call. Phase 6 was asked to settle
it, so it was settled — in favour of the code, with the documentation corrected.

`ARCHITECTURE.md` section 15 claimed "a threshold of zero is refused… it would flag every item
forever." The code accepts zero, and the comparison is `quantity <= threshold`, so a zero
threshold flags an item **only while its quantity is zero**. The reason the old rule gave is
simply false of the rule that exists. The PRD says nothing about zero; the schema has no
constraint; and `scripts/domain-test.mjs` and `scripts/dashboard-test.mjs` both already asserted
the surviving behaviour.

Refusing zero was rejected for a second reason too: it would remove a capability the user can
reasonably want — "tell me when I am out" — and the only way to express it afterwards would be to
leave the field empty, which *disables* the flag. A refusal that makes the request unreachable is
not a safer rule.

ADR-048 records it. `NULL` remains the only value that turns the flag off, and the two stay
distinguishable. No code changed; the documentation now matches.

## Two real defects found along the way

**A Phase 4 test that depended on the wall clock.** `scripts/expenses-test.mjs` pinned
`2026-10-01T12:00:00.000Z` for its same-millisecond tie-break case and asserted those rows were
newest. True only before noon that day. At 12:00 UTC it began failing on its own —
`256 passed, 1 failed`. Confirmed pre-existing by stashing the phase's work and re-running: the
same failure. The timestamp is now read from the clock, with a comment explaining why a hard-coded
one was wrong.

**A fourth nav link broke every page at 320px.** Adding Routine to the nav made four links wider
than a small phone. `body { overflow-x: hidden }` hid it in a browser; `responsive:check` reported
*every* element on the page as overflowing. `.nav` now wraps, which is the entire fix. The check
was also asserting a link **count** of three — the assertion a navigator stops maintaining the
moment a page is added — so it now asserts the names.

One more defect was found and fixed before either was visible to a user: `recordNightTime` mapped
the column name `wake_time` onto a row property that did not exist, so the executor's read-back
found `undefined` and stored an empty string in a nullable column. The domain now carries the
parsed time on the change, so the executor stores what the domain parsed and cannot derive an
empty one.

### Boundary enforcement, probed not asserted

`src/features/routine/**` is a new enforced scope in `eslint.config.mjs`: no storage, no driver,
no filesystem, no provider module, no `@/commands/executor`, and no other feature's write side.
`npm run architecture:probe` proves each of those rules **fires** — six refusals — and that the
imports the architecture permits still pass — two allowances. 47 checks in total. A rule that
rejected everything would still satisfy the refusals, which is why the allowances are counted.
